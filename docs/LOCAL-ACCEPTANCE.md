# v0.7.0 环境管理验收说明

本轮环境管理、代理编辑、默认检测页与macOS序号图标改进已完成本地验收，纳入0.7.0发布。IP性质（家宽/机房）检测暂缓，未接入IPLark或Ping0。

## 验收步骤

先退出正在运行的旧CIKE，打开安装后的 `CIKE.app`（源码验收可使用 `dist/local-preview/CIKE-darwin-arm64/CIKE.app`）。它默认沿用原数据目录；建议先用新建测试环境验收。旧版环境的原生一致模式转换规则沿用0.6.0。

1. 同时打开两个环境。关闭其中一个环境的最后一个窗口，检查它的窗口、进程和运行状态消失，另一个环境继续运行。管理页点击关闭也应结束整个环境；多标签页只关闭一页不会退出其余页。启动中可点击“取消启动”。配置、Cookie和站点数据保留，只有“删除”才删除环境数据。
2. 在环境卡片点击蓝色代理地址/IP。复制 `socks5://用户:密码@主机:端口` 或 `主机:端口:用户:密码` 后打开编辑窗口，应自动填入字段；也可以粘贴到整行输入框或点击“读取剪贴板”。支持HTTP、HTTPS、SOCKS5、URL认证编码和括号IPv6。只在打开此编辑窗口或主动点击时读取剪贴板，不轮询。
3. 修改单个环境代理后，其他引用同一已保存代理的环境应不变。运行中的当前环境会先关闭再保存；选择“保存并检测”会更新出口IP，检测失败保留设置并显示原因。无检测结果时显示代理服务器地址，不把服务器地址冒充出口IP。
4. 管理页显示“创建”和“最后打开”时间。新环境最后打开显示“尚未打开”；成功启动后记录时间，重复点击正在运行的环境不刷新该时间，重启管理器后仍保留。历史没有记录的打开时间不会猜测补填。
5. 新打开的有界面环境进入CIKE环境检测页，显示环境序号、当前出口IP、地区、浏览器/出口时区、语言和运营商。点击重新检测可以刷新；网络失败显示失败，不改用宿主网络代查。IP与启动检测不一致或时区不同会提示。外部请求由该浏览器直接通过当前网络设置发出。
6. macOS Dock环境图标采用铺满画布的背景，去掉透明边距和内层圆角框；顶部显示放大的序号，下方显示裁去原图边距的CIKE标志。首次为环境准备图标会增加几秒启动时间；之后复用，内核或图标版本变化时重建。每个环境具有独立bundle identifier，沙盒继续开启。修复了原内核的`CFBundleIconName=AppIcon`让macOS优先读取Chrome Test资产图标的问题；旧缓存会自动更新。

## 实现与边界

- 环境列表采用紧凑分栏布局，宽窗口中普通卡片约82像素高，长名称或窄窗口允许换行。环境每页12条、代理每页15条，超过后显示分页控件；已验证25个环境和31个代理的翻页及环境跨页勾选。

- 默认页使用仅在本环境页面内拦截的 `https://start.cike.invalid/`，不在本地新增监听端口、不暴露管理API Token或代理密码。出口检测访问api.ipify.org，地区信息访问ipwho.is，服务故障不会自动更换网络。
- macOS图标使用系统AppKit绘制，不依赖Python/Pillow。每环境使用独立内核包副本，APFS优先使用写时复制，避免旧实现的可执行文件符号链接。修改并ad-hoc签名的是环境副本，下载的原内核不改动。非APFS卷可能占用更多磁盘空间；删除环境会删除相应副本。
- 关闭结束运行进程，不抹除登录数据，也不删除用户手动固定在Dock中的图标。macOS自身的“最近使用的应用”显示由系统控制。
- “保存并检测”是保存后检测，网络失败不撤回用户输入；下次启动仍执行既有代理失败阻断规则。

## 验证

新增环境测试覆盖整行代理解析、单环境代理独立性与脱敏、IP元数据、关闭最后窗口与其他环境继续运行、真实macOS序号图标启动及签名、最后打开时间持久化、取消启动和默认页检测/刷新/失败处理。

`npm run test:icons`额外读取正在运行的`NSRunningApplication.icon`，核对实际应用图标的CIKE配色/数字图案，而不只检查磁盘文件；也验证旧图标缓存重建。macOS可能为传统ICNS添加系统玻璃边框或颜色处理，因此比较允许系统缩放与色彩差异。

`npm test`共13组通过，既有沙盒、五类存储隔离、网络和下载测试保留。桌面测试验证剪贴板自动填充、保存、环境时间显示和真实点击打开/关闭。构建后的应用另行进行同样的桌面操作测试。
